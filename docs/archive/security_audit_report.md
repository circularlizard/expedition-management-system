## 1. Outgoing External HTTP Requests & SSRF Mitigation
WordPress plugins communicating with external APIs should verify the destinations of remote requests to protect the server from Server-Side Request Forgery (SSRF) attacks.

### Finding 1.1: Raw `wp_remote_post` in OAuth Callback
* **File:** [OSM_Sync_Auth_Handler.php](file:///Users/davidstrachan/Projects/expedition-management-system/src/Admin/OSM_Sync_Auth_Handler.php#L171-L182)
* **Risk:** Medium (Potential SSRF if the dynamic `$this->token_url` option is misconfigured or points to an internal loopback network).
* **Fix:** Replace `wp_remote_post` with `wp_safe_remote_post`.

#### Code Refactor:
```diff
-		$response = wp_remote_post(
+		$response = wp_safe_remote_post(
 			$this->token_url,
 			array(
 				'body' => array(
```

* **File:** [Live_Driver.php](file:///Users/davidstrachan/Projects/expedition-management-system/src/Integrations/Drivers/Live_Driver.php#L35)

## 2. Sensitive Credential & Data Leak Prevention
Sensitive keys, tokens, or personal identifiers must not be dumped into server logs where they could be accessed by unauthorized server administrators or logged externally.

### Finding 2.1: Logging of Bearer Tokens in live API requests
* **File:** [Live_Driver.php](file:///Users/davidstrachan/Projects/expedition-management-system/src/Integrations/Drivers/Live_Driver.php#L31-L32)
* **Risk:** High (Bearer Token details, although partially truncated, are written directly to `error_log` alongside the request URL).
* **Fix:** Remove debug logging of Authorization headers entirely.

#### Code Refactor:
```diff
 		$auth = $args['headers']['Authorization'] ?? 'None';
 		if ( $auth !== 'None' ) {
 			$auth = substr( $auth, 0, 18 ) . '... (len: ' . strlen( $auth ) . ')';
 		}
-		error_log( '[EMS Debug] Request URL: ' . $url );
-		error_log( '[EMS Debug] Request Authorization Header: ' . $auth );
```

## 3. Test Suite Bootstrap & Mock Isolation Issues
The unit tests contain bootstrap state pollution due to un-isolated mock database queries.

### Finding 3.1: Persisted `global $wpdb` mock state causes crashes
* **File:** `tests/Unit/Auth/OIDC_Login_HandlerTest.php` and `tests/Unit/Integrations/Fluent_Forms_SyncTest.php`
* **Root Cause:** Multiple tests mock `global $wpdb` but do not cleanly teardown/reset the global variable or close Mockery expectations (`Mockery::close()`). As a result, subsequent test executions hit method-not-found errors (`get_col() does not exist`).
* **Fix:** Ensure `$wpdb` is mock-isolated in OIDC test setup, and call `Mockery::close()` during tearDown.
